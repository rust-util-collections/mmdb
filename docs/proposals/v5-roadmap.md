# MMDB v5 Structural & Wire-Format Roadmap

Status: implemented in the v5.0.0 working tree. The design below records the v4.3 baseline. Current API and migration instructions are in the [README](../../README.md).

The core accepts v5 MANIFEST and SST formats. A [standalone exporter](../../tools/v4-export/Cargo.toml) links MMDB 4.3.15 to read older stores. WAL batch framing stays byte-identical. Index and rangedel directories use linked, individually checksummed pages so an aggregate directory can grow past the single-block size limit. Read-only open adopts the persisted level count and prefix length. Writable open requires both to match.

Verification includes eight Miri seeds across two alias models, WAL seal and MANIFEST fault injection, a simulated loss of unsynced WAL pages, and a v4 golden-store conversion. On the same 200,000 absent keys, v5 at 12 bits/key measured 0.59% false positives (`0.566%` analytical expectation under 32-bit affine intra-line probing vs the `0.407%` 512-bit Poisson floor under independent probes) and the v4.3.15 filter at 10 bits/key measured 0.86%. The 120,000-entry arena test allocated 8,384,512 slab bytes (`69.9 B/entry` including active slab tail) for distinct 16-byte keys and 16-byte values. Section 7 below records the post-cutover quantitative benchmark evaluation across `benchmarks` and `v5_profile` together with the `v5.x` structural optimization designs addressing the remaining read, iterator, filter, write-pipeline, and bulk-ingestion bottlenecks.

Baseline: `cecc9b3` (`v4.3.15`), co-designed with `vsdb` v18 ([vsdb v18 roadmap](../../../vsdb/docs/proposals/v18-roadmap.md)).

## Scope boundary: what genuinely requires v5 vs. v4.x?

MMDB keeps all internal modules private and exports only the curated root surface in [src/lib.rs](../../src/lib.rs#L58-L71). Several `v4.3` releases already landed major internal wins compatibly (`TableReader::find_data_block` using `cached_index_entries` at [table_reader/mod.rs](../../src/sst/table_reader/mod.rs#L480), `Block::seek_by_reuse`, `ArcSwap` block-pin reads at [block_cache.rs](../../src/cache/block_cache.rs#L210), `Version` per-level `Arc` sharing at [version.rs](../../src/manifest/version.rs#L24-L26), `Cow::Borrowed` uncompressed SST writes at [table_builder.rs](../../src/sst/table_builder.rs#L508-L528), and `RateLimiter`'s zero-rate early return at [rate_limiter.rs](../../src/rate_limiter.rs#L145-L148)).

`v5.0.0` unites **six co-designed pillars** paired with `vsdb` v18, cleanly distinguishing true SemVer / on-disk breaks from additive or internal upgrades that can prototype or land compatibly in `v4.x` ahead of the `v5.0.0` cutover:

1. **Public safety & option-extensibility breaks** *(breaking public API)*: `#[non_exhaustive]` options with full builders, `Cow<'a, [u8]>` read bounds, live DB-bound `SnapshotRef<'a>` / `ArcSnapshot` handles in `ReadOptions` (closing the `db.snapshot().read_options()` temporary-drop MVCC hazard), `DurabilityMode` enum (eliminating contradictory `sync: true, disable_wal: true` and its mixed-group fsync side effect), and **key-only + post-MVCC-enforced `BlockPropertyCollector` / `BlockPropertyFilter`** (fixing present value-filter and cross-level block-skipping MVCC resurrection);
2. **Zero-copy & zero-fence engine primitives** *(additive APIs + breaking iterator error signatures)*: `DB::get_pinned` (`PinnedSlice`), value-free `DB::contains_key`, seal-aware `DB::sync_wal` *(all three additive in `v4.x`)*, plus typed `Option<&Error>` on iterators and fallible lending `step_next` / `step_prev` cursors *(breaking in `v5.0`)*;
3. **Flat WAL-native `WriteBatch` + scatter-gather prefixed writes** *(internal + additive on `WriteBatch`; breaking only on `WriteBatchWithIndex::range_tombstones`)*: single-buffer v4-WAL-identical `WriteBatch` with `WalWriter::add_record_parts` vectored group commit (eliminating per-entry `Vec` allocations, `encode_wal_record` copying under `DB::inner`, and in-place request mutation) while replacing `WriteBatchWithIndex`'s owned-tuple slice accessor;
4. **Inline-arena variable-height `MemTable`** *(internal, `v4.x`-compatible)*: 8B-aligned raw-slab skiplist cutting small-KV structural overhead by ~86% (~190B → ~27B, ~2–3.4× write-buffer density) and freeing slabs in `O(slabs)` without per-node `Vec` destructor walks;
5. **Non-blocking FIFO immutable-MemTable flush pipeline & unlocked level sweeps** *(behavioral activation of existing `max_immutable_memtables`)*: leader-unlocked WAL-seal rotation, newest-first read / oldest-first install `VecDeque` (fixing a latent oldest-first ordering bug in `immutable_memtables`), generation-gated `flush`/`close`, and full-level unlocked `force_merge_level` / `lazy_delete` sweeps;
6. **`MANIFEST` v2 & SST v2 on-disk formats** *(breaking on-disk format, gated early via `DBHeader`)*: crash-atomic `MANIFEST` `DBHeader` (`format_version = 5`, exact `num_levels`, `prefix_len`) landed first as the version gate, followed by 64B cache-line-blocked XXH3-64 Bloom filters (`filter.format = 2`), `InternalKey`-valid shortest separators + independent-restart partitioned index, and pre-fragmented clipped partitioned `rangedel` blocks.

## 1. Public configuration, MVCC snapshot lifetimes, and MVCC-sound block properties

Source: [options.rs](../../src/options.rs), [db.rs](../../src/db.rs#L2451-L2463), [db.rs](../../src/db.rs#L3346-L3349), [db.rs](../../src/db.rs#L4522-L4550), [compaction/leveled.rs](../../src/compaction/leveled.rs#L1641-L1650), [sst/table_builder.rs](../../src/sst/table_builder.rs#L392-L394), [table_reader/iterator.rs](../../src/sst/table_reader/iterator.rs#L181-L192), [iterator/db_iter.rs](../../src/iterator/db_iter.rs#L482-L497).

### Current contract hazards and friction

1. **Dangling `Snapshot` sequence footgun (`db.snapshot().read_options()`) — surfaces future values:**
   [`Snapshot::read_options`](../../src/db.rs#L4538-L4543) (`Snapshot` is not `#[must_use]`) borrows `&self` only for the call and copies a raw `u64` into `ReadOptions::snapshot: Option<SequenceNumber>` ([options.rs](../../src/options.rs#L259)). Writing `let opts = db.snapshot().read_options();` immediately drops the temporary `Snapshot`, calling `release_snapshot` ([db.rs](../../src/db.rs#L2458-L2463)). Once unregistered, not only can compaction reclaim historical versions and run `CompactionFilter`, **bottommost sequence zeroing ([compaction/leveled.rs](../../src/compaction/leveled.rs#L1641-L1650)) rewrites newer `Value` entries below `oldest_snapshot_seq` to `seq = 0`** — so reading at the dead sequence `7` after `k = v2@10` compacts to `k = v2@0` silently returns the **future value `v2`** (or phantom newer keys)! Passing DB `A`'s raw sequence to DB `B` also silently clamps via `s.min(committed)` ([db.rs](../../src/db.rs#L3346-L3349)). *(Note: `#[must_use]` on `Snapshot` and additive `Snapshot::{get, iter*}` methods can land in `v4.x` immediately.)*
2. **MVCC resurrection via `BlockPropertyCollector` / `BlockPropertyFilter`:**
   [`TableBuilder::add`](../../src/sst/table_builder.rs#L392-L394) passes the **encoded internal key** (`user_key || 8B trailer`) and `value` to [`BlockPropertyCollector::add(&mut self, key: &[u8], value: &[u8])`](../../src/options.rs#L380) (`Value` carries user bytes; `Deletion` carries `&[]`; `RangeDeletion` goes separately to `rangedel` at [table_builder.rs](../../src/sst/table_builder.rs#L284-L302)). [`TableIterator`](../../src/sst/table_reader/iterator.rs#L181-L192) then skips physical blocks per SST across `seek` ([L312](../../src/sst/table_reader/iterator.rs#L312)), `seek_for_prev` ([L469](../../src/sst/table_reader/iterator.rs#L469)), `prev` ([L582](../../src/sst/table_reader/iterator.rs#L582)), `next` ([L683](../../src/sst/table_reader/iterator.rs#L683)), and `seek_to_last` ([L849](../../src/sst/table_reader/iterator.rs#L849)) **before `DBIterator` deduplicates across levels**, with no level restriction:
   - *Value-predicate resurrection:* if `k = "red"@5` lives in L1 and `k = "blue"@10` (or `Deletion@10`) lives in an L0 block with no `"red"` values, skipping that L0 block resurrects stale `k = "red"@5`.
   - *Non-matching-key resurrection (even with key-only collectors!):* for key predicate $P$ (e.g. prefix `"a_"`), an L0 block holding only `b1@10` is skipped (`should_skip == true`), whereas a mixed L1 block holding `(a_x@5, b1@5)` is kept (`should_skip == false`) — yielding stale or deleted `b1@5` unless `DBIterator` also rejects keys with $\neg P(k)$ after MVCC merge!
3. **Contradictory `WriteOptions` flags, exhaustive option structs, and per-level option clones:**
   - `WriteOptions { sync: true, disable_wal: true }` ([options.rs](../../src/options.rs#L309-L316)) is representable: when grouped alone it performs no fsync ([db.rs](../../src/db.rs#L3616-L3630)), yet in a mixed group `need_sync |= r.sync` ([db.rs](../../src/db.rs#L3612)) forces an `fsync` on peer WAL writers even though the caller's own batch skipped the WAL (`v4.x` can tighten this to `r.sync && !r.disable_wal`).
   - `DbOptions`, `ReadOptions`, and `WriteOptions` lack `#[non_exhaustive]` ([read-only-mode.md](read-only-mode.md#L83-L85)); `ReadOptions::{iterate_lower_bound, iterate_upper_bound}` (`Option<Vec<u8>>`) force caller heap allocations; and iterator construction clones both bound `Vec`s and `block_property_filters: Vec<Arc<...>>` across every L0 iterator, `LevelIterator`, and opened SST ([db.rs](../../src/db.rs#L1989-L2015), [db.rs](../../src/db.rs#L2096-L2097), [iterator/level_iter.rs](../../src/iterator/level_iter.rs#L236-L241)).
   - `DbOptions::pin_l0_filter_and_index_blocks_in_cache` ([options.rs](../../src/options.rs#L90-L96)) explicitly notes its name matches RocksDB only (index/filter blocks live on `TableReader`, never in `block_cache`; the flag warms `cached_index_entries` and pins each L0 file's first data block).

### v5 design

1. **Live, DB-verified `SnapshotRef<'a>` + `ArcSnapshot` (`#[must_use]`):**
   - Tag each open `DB` with a process-unique `db_id: u64` and mark both `Snapshot<'db>` and `ArcSnapshot` `#[must_use]`. Expose `pub enum SnapshotRef<'a> { Borrowed(&'a Snapshot<'a>), Shared(&'a ArcSnapshot) }` (with `From` impls) in `ReadOptions<'a>::snapshot: Option<SnapshotRef<'a>>`.
   - `ArcSnapshot` holds `Arc<SnapshotLease>` (`db_id`, `closed: Arc<AtomicBool>`, `SnapshotList`, `DeadKeySweepState`, and compaction-wakeup handle — without retaining `TableCache` or `LOCK`), so `ArcSnapshot::drop` still triggers `dead_key_sweep.retry_after_snapshot_release()` + `signal_compaction()` ([db.rs](../../src/db.rs#L2458-L2463)) when open, while reads via `ArcSnapshot` after `DB::close()` return `Err(ErrorKind::DbClosed)`.
   - Compaction cannot reclaim or zero sequence numbers below a live `SnapshotRef<'a>`, and cross-DB snapshots (`snapshot.db_id != self.db_id`) return `Err(ErrorKind::InvalidArgument)`. Add direct `snapshot.get(key)`, `snapshot.get_pinned(key)`, `snapshot.contains_key(key)`, and `snapshot.iter*()`.
2. **Key-only + post-MVCC-enforced `BlockPropertyCollector` & `BlockPropertyFilter`:**
   - Change `BlockPropertyCollector::add(&mut self, user_key: &[u8])` to receive **only `user_key`** (stripped of internal trailer, invoked for both `Value` and `Deletion` entries in the data block).
   - Add `fn key_matches(&self, user_key: &[u8]) -> bool` to `BlockPropertyFilter` and enforce two invariants: (a) **monotonic over-approximation** — if `key_matches(k)` is `true` for *any* `user_key` passed to `collector.add(k)` in a block, `should_skip(props)` **must** return `false`; (b) **post-MVCC row filtering** — `DBIterator` checks `filter.key_matches(user_key)` after cross-level MVCC deduplication (alongside `skip_point` at [iterator/db_iter.rs](../../src/iterator/db_iter.rs#L482-L497), [L905-L910](../../src/iterator/db_iter.rs#L905-L910)). Thus matching keys never skip any block holding a newer overwrite/tombstone, and non-matching keys from partially matching blocks are never yielded with stale historical values. Document that each collector `name()` has immutable semantics for the lifetime of a store and that point `DB::get*` ignores iterator block filters.
3. **`DurabilityMode`, `#[non_exhaustive]` builders, `Cow<'a, [u8]>` bounds, and shared `Arc<IterConfig>`:**
   - Replace `WriteOptions::{sync, disable_wal}` with `pub enum DurabilityMode { WalAsync, WalSync, DisableWal }`.
   - Add `#[non_exhaustive]` and complete builder APIs to `DbOptions`, `ReadOptions<'a>`, and `WriteOptions` (required because `#[non_exhaustive]` disallows external `..Default::default()` struct literals). Use `Cow<'a, [u8]>` for `iterate_lower_bound` / `iterate_upper_bound` so long-lived struct fields can hold `ReadOptions<'static>` while stack callers pass borrowed `&'a [u8]` slices with zero allocation. Because `DBIterator` is `'static`, copy bounds once at iterator creation into a single `Arc<IterConfig>` (holding `lower_bound`, `upper_bound`, and `Arc<[Arc<dyn BlockPropertyFilter>]>`), eliminating per-level and per-SST `Vec` clones.
   - Rename `pin_l0_filter_and_index_blocks_in_cache` to `pin_l0_first_block_and_warm_index: bool`.

## 2. Zero-copy `PinnedSlice`, value-free `contains_key`, seal-aware `sync_wal`, and typed iterator cursors

Source: [db.rs](../../src/db.rs#L1699-L1758), [db.rs](../../src/db.rs#L3573-L3575), [iterator/db_iter.rs](../../src/iterator/db_iter.rs#L19-L70), [iterator/db_iter.rs](../../src/iterator/db_iter.rs#L593-L608), [iterator/bidi_iter.rs](../../src/iterator/bidi_iter.rs#L111-L128), [sst/block.rs](../../src/sst/block.rs#L479), [sst/table_reader/mod.rs](../../src/sst/table_reader/mod.rs#L690-L717).

### Current limitations

1. **Forced result-value copy on `DB::get` and `contains_key`:**
   `DB::get_with_options` copies the matched value out of `MemTable` or `BlockCache`'s decompressed `Arc<Vec<u8>>` even when `vsdb` only binary-searches a slotted B+ tree page (`NodeView`), computes vector distance, or checks key existence (`MapxRaw::contains_key`).
2. **No native `DB::sync_wal`:**
   `vsdb` currently issues `delete_with_options(sync=true, META_KEY_WAL_FENCE)` to fence prior `WalAsync` commits without flushing memtables.
3. **Stringified iterator errors:**
   While `BlockIterator` already retains `Option<Error>` ([sst/block.rs](../../src/sst/block.rs#L479)), `TableIterator`, `LevelIterator`, `MergingIterator`, `DBIterator::error`, and `BidiIterator::error` stringify failures into `Option<String>`, losing `ErrorKind` and `source()`.

### v5 design

1. **`PinnedSlice` (`DB::get_pinned` / `DB::get_pinned_with_options`):**
   - `pub struct PinnedSlice` implements `Deref<Target = [u8]>`, `AsRef<[u8]>`, and `into_vec(self) -> Vec<u8>`, backed by an internal enum over SST block `(Arc<Vec<u8>>, offset: u32, len: u32)` (both cached and `fill_cache = false` reads already wrap `Arc<Vec<u8>>` at [table_reader/mod.rs](../../src/sst/table_reader/mod.rs#L690-L717) with zero `unsafe`), memtable `(Arc<MemTable>, NonNull<u8>, len: usize)` (`Send + Sync` invariant in §4; also feasible on `v4.x` `Vec`-backed nodes or via an `Owned(Vec<u8>)` variant before §4 lands), and `Owned(Vec<u8>)`. Generalizing memtable lookup to borrowed `(user_key: &[u8], seq)` plus stack-buffering short internal SST seek keys (`<= 120`B) removes point-get scratch heap allocations.
   - **Explicit retention contract:** Document that holding a `PinnedSlice` retains its backing `Arc<Vec<u8>>` block (up to `MAX_DECOMPRESSED_BLOCK_SIZE` = 64 MiB for oversized values) or `Arc<MemTable>` (~64 MiB `write_buffer_size` arena) outside cache/write-buffer budgets even after compaction, eviction, or `DB::close()`; callers retaining values beyond transient inspection must call `.into_vec()`.
2. **Value-free `DB::contains_key` / `DB::contains_key_with_options`:**
   - Execute full `SuperVersion` MVCC + range-tombstone visibility resolution inspecting only internal-key trailers (`ValueType::Value` vs `Deletion`), returning `Result<bool>` with zero value copies.
3. **Cross-rotation-safe `DB::sync_wal(&self) -> Result<()>`:**
   - **Async-flush WAL rotation invariant:** Once §5 runs background flushes, an earlier `WalAsync` commit may live in rotated WAL `W0` (flush in flight) while `active_memtable` appends to `W1`. Because §5 seals (`flush` + `sync_data`) `W0` and confirms `Ok(())` **before** publishing `W1`, any committed write in a rotated WAL is already durable; `sync_wal()` tracks `synced_wal_seq: AtomicU64`, returns immediately if `synced_wal_seq >= target_committed_seq`, and otherwise enqueues a dedicated `WriteRequestKind::WalFence { target_seq }` onto `write_queue` — bypassing **both** `write_with_options`'s `batch.is_empty()` check ([db.rs](../../src/db.rs#L1705)) and `write_batch_group`'s `total_ops == 0` early return ([db.rs](../../src/db.rs#L3573-L3575)) so fence requests coalesce with active group-commit leaders and trigger `set_bg_error` fail-stop on `sync_data()` failure.
4. **Typed `Option<&Error>` and fallible lending `step_next` / `step_prev`:**
   - Propagate typed `Option<Error>` (`Error` is already `Clone + Send + Sync`) end-to-end through `TableIterator`, `LevelIterator`, `MergingIterator`, `DBIterator::error(&self) -> Option<&Error>`, and `BidiIterator::error(&self) -> Option<&Error>`.
   - Unify `DBIterator`'s existing internal borrowed cursor (`valid` / `key` / `value` / `advance` / `prev` at [iterator/db_iter.rs](../../src/iterator/db_iter.rs#L617-L961)) and `BidiIterator` (`Lazy` and `Materialized` variants) behind `step_next(&mut self) -> Result<Option<(&[u8], &[u8])>>` and `step_prev(&mut self) -> Result<Option<(&[u8], &[u8])>>`.
   - **Intentional error-precedence break from `v4.3`:** [`DBIterator::ensure_current`](../../src/iterator/db_iter.rs#L593-L605) currently preserves an already-resolved candidate row when lookahead into the next block latches a read error, surfacing the error only on the *following* step. In v5, if deduplication lookahead or source advancement encounters an `Error` during `step_next` / `step_prev`, the cursor latches the error and returns **`Err(err.clone())` immediately** (never `Ok(Some(row))`), matching `vsdb`'s post-step `CheckedBidiIter` invariant ([vsdb mmdb.rs](../../../vsdb/core/src/common/engine/mmdb.rs#L629-L657)).

## 3. Flat WAL-native `WriteBatch` and zero-mutation group-commit framing

Source: [types.rs](../../src/types.rs#L288-L468), [db.rs](../../src/db.rs#L460-L475), [db.rs](../../src/db.rs#L1699-L1709), [db.rs](../../src/db.rs#L2334-L2345), [db.rs](../../src/db.rs#L3409-L3680), [db.rs](../../src/db.rs#L4225-L4416), [wal/writer.rs](../../src/wal/writer.rs#L75-L120).

### Current costs

`WriteBatch` ([types.rs](../../src/types.rs#L289-L298)) allocates per-entry `key: Vec<u8>` (plus `value: Vec<u8>` on puts/range-deletes), and [`encode_wal_record`](../../src/db.rs#L4225-L4248) allocates and copies every batch into a second `Vec<u8>` while holding `DB::inner`.

### v5 design

1. **Contiguous v4-WAL-identical `WriteBatch` with checked admission:**
   - Store `payload: Vec<u8>`, `count: u32`, and `invalid: Option<Error>` (1 contiguous buffer per constructed batch, reusable via `WriteBatch::with_capacity` + `clear()`).
   - Pin `payload` **byte-for-byte to the v4 WAL record body** ([db.rs](../../src/db.rs#L4236-L4245), replayed at [db.rs](../../src/db.rs#L4346-L4416)) so WAL replay stays identical across v4/v5:
     - `Value` (`1`): `[1u8 | key_len: u32 LE | key | val_len: u32 LE | val]`
     - `Deletion` (`0`): `[0u8 | key_len: u32 LE | key]` *(no `val_len` field)*
     - `RangeDeletion` (`2`): `[2u8 | begin_len: u32 LE | begin | end_len: u32 LE | end]` *(no-op `begin >= end` skipped before incrementing `count`, matching [types.rs](../../src/types.rs#L329))*
   - Provide `put`, `delete`, `delete_range` (retaining raw `delete_range(begin, end)` for cross-prefix wipes such as `vsdb`'s `[prefix, prefix_successor(prefix))`), **plus** scatter-gather `put_prefixed(prefix, key, value)`, `delete_prefixed(prefix, key)`, and `delete_range_prefixed(prefix, begin, end)`.
   - Validate checked lengths (`prefix.len().checked_add(key.len())`, charging `2 * prefix.len()` on `delete_range_prefixed`), **both** `begin` and `end` against `MAX_USER_KEY_SIZE` (closing today's missing `end.len() <= MAX_USER_KEY_SIZE` check), `MAX_WRITE_ENTRY_SIZE` / `MAX_RANGE_DELETE_SIZE`, and `count < u32::MAX` **before** appending: on violation, latch `self.invalid` without mutating `payload`/`count`, and check `batch.invalid` **before** `batch.is_empty()` in **both** `write_with_options` ([db.rs](../../src/db.rs#L1705)) and `write_batch_inner` ([db.rs](../../src/db.rs#L3420)).
2. **Vectored `WalWriter::add_record_parts` — zero `WriteRequest` mutation under Stacked/Tree Borrows:**
   - Waiting writer threads may wake spuriously and read `(*req_ptr).done` under `write_queue` while the leader runs unlocked ([db.rs](../../src/db.rs#L460-L469)), and mutating `(*req_ptr).batch` via `Vec::as_mut_ptr` while a shared `let r = &*req_ptr` borrow is live ([db.rs](../../src/db.rs#L3598), [L3644](../../src/db.rs#L3644)) would violate Stacked/Tree Borrows!
   - Because group commit already writes **one WAL record per batch** ([db.rs](../../src/db.rs#L3595-L3613)), add `WalWriter::add_record_parts(&mut self, parts: &[&[u8]])` ([wal/writer.rs](../../src/wal/writer.rs#L75-L120)) and pass `[&header_12b /* [first_seq: u64 LE | count: u32 LE] */, batch.payload.as_slice()]` directly. The leader **never mutates `(*req_ptr).batch`** at all — reading `batch` and `durability` purely via shared/raw-const field projections and writing only `(*req_ptr).result` and `(*req_ptr).done`!
3. **Redesigned `WriteBatchWithIndex` (`WBWI`):**
   - Because `batch.payload` can reallocate as entries are appended, store `BTreeMap<Box<[u8]>, (usize, u64)>` (one compact key allocation per *distinct* user key in the indexed batch, mapping to `(entry_offset, write_pos)` in `batch.payload` with zero duplicate value storage) plus `Vec<(usize, u64)>` for range tombstones.
   - Gate index updates on `self.batch.invalid.is_none()` so rejected entries are never indexed, check `batch.invalid` in `iter_with_batch*` ([db.rs](../../src/db.rs#L2334)) and `into_batch()`, and replace `pub fn range_tombstones(&self) -> &[(Vec<u8>, Vec<u8>, u64)]` ([types.rs](../../src/types.rs#L430)) with an iterator yielding borrowed `(&[u8], &[u8], u64)` slices decoded from `batch.payload`.

## 4. Inline-arena variable-height `MemTable` (`unsafe` layout, splice, & overshoot bounds)

Source: [memtable/skiplist_impl.rs](../../src/memtable/skiplist_impl.rs#L43-L271), [memtable/mod.rs](../../src/memtable/mod.rs#L65-L180), [db.rs](../../src/db.rs#L3511).

### Current overhead

Each skiplist `Node` ([skiplist_impl.rs](../../src/memtable/skiplist_impl.rs#L121-L129)) embeds a fixed 12-level `AtomicPtr` tower (96B) plus two `Vec<u8>` headers (48B) and header padding = **152B**, plus two separate heap allocations (~64B allocator chunks on 16B/16B KVs) and an `all_nodes: Vec<*mut Node>` slot (~8–16B) — **~190B of structural overhead for 40B of payload (~224–232B total)**, walked node-by-node in `Drop` ([skiplist_impl.rs](../../src/memtable/skiplist_impl.rs#L572-L585)).

### v5 design

1. **Checked `Layout` composition, raw-pointer slabs, and `>256 KiB` dedicated blocks:**
   - Manage slabs directly as `(NonNull<u8>, Layout)` pairs via `std::alloc::alloc` / `dealloc` (growing `4 KiB -> 1 MiB` `ARENA_MAX_BLOCK`) to keep raw pointer provenance explicit without `Vec` wrapper headers, paired with a standalone Miri test target exercising concurrent `Arena` + `SkipList` inserts and `PinnedSlice` reads without filesystem `DB` I/O.
   - Lay out each node with `#[repr(C, align(8))] struct NodeHeader { key_len: u32, val_len: u32, height: u8, _pad: [u8; 7] }` (16B), followed by `tower: [AtomicPtr<NodeHeader>; height]` (average $4/3 \times 8\text{B} \approx 10.7\text{B}$ at $p = 1/4$), `internal_key: [u8; key_len]`, and `value: [u8; val_len]` via checked `Layout::extend` — cutting small-KV structural overhead from ~190B to **~27B (~86% overhead reduction; ~3.4× density on 16B/16B KVs, ~2.0× on 100B values)**.
   - Route nodes larger than `ARENA_MAX_BLOCK / 4` (`256 KiB`) directly to dedicated exact-sized slabs so inline large values cannot strand up to `1 MiB` of unused tail space in the active slab.
   - `unsafe impl Send / Sync for PinnedSlice` relies on three invariants: (a) node payload bytes are fully written before the level-0 `Release` publish and never mutated; (b) `Arc<MemTable>` retains every slab until the last reader/slice drops; (c) `MemTable` exposes no in-place clear/reuse API.
2. **Pre-initialized tower + bottom-up `Release` splice ([skiplist_impl.rs](../../src/memtable/skiplist_impl.rs#L252-L271)):**
   - Initialize `NodeHeader`, `internal_key`, `value`, **and all `node.tower[0..height]` slots** (`Relaxed` stores of `old_next[level]` loaded from `head[level]` / `(*prev[level]).tower[level]`) **before** publishing level 0 — ensuring higher tower slots are never uninitialized once level 0 is visible to concurrent readers (single-writer serialization under `DB::inner` guarantees `old_next[level]` cannot change mid-insert).
   - Publish `pred_slot[level].store(node, Ordering::Release)` for `level in 0..height` (paired with reader `Ordering::Acquire` loads), and update `tail` when `old_next[0].is_null()`.
3. **Exact slab accounting and bounded write-group size:**
   - Account **allocated/consumed slab bytes** (including any abandoned slab tail) plus separate `MemRangeTombstone` `Vec` bytes ([memtable/mod.rs](../../src/memtable/mod.rs#L79-L94); range tombstones still allocate endpoint `Vec`s), and delete `all_nodes` (`MemTable::drop` frees ~64 raw slabs + range tombstones).
   - Cap each group-commit drain ([db.rs](../../src/db.rs#L3511)) at `MAX_WRITE_BATCH_GROUP_BYTES` (e.g., `min(write_buffer_size / 2, 16 MiB)`, always admitting at least the head batch) so concurrent writers cannot overshoot `write_buffer_size` unboundedly in a single leader turn.

## 5. Non-blocking FIFO flush pipeline, leader-unlocked WAL rotation, and unlocked sweeps

Source: [options.rs](../../src/options.rs#L24-L30), [db.rs](../../src/db.rs#L266-L291), [db.rs](../../src/db.rs#L909-L974), [db.rs](../../src/db.rs#L1740-L1750), [db.rs](../../src/db.rs#L2632-L2865), [db.rs](../../src/db.rs#L3113-L3185), [db.rs](../../src/db.rs#L3682-L3995), [db.rs](../../src/db.rs#L4186-L4220), [compaction/leveled.rs](../../src/compaction/leveled.rs#L1299), [manifest/version_set.rs](../../src/manifest/version_set.rs#L562-L575), [tests/crash_recovery.rs](../../tests/crash_recovery.rs#L706-L763).

### Critical invariants verified against MMDB recovery & MVCC

1. **Leader-unlocked WAL sealing, `wal_bytes_per_sync` smoothing, & seal fail-stop:**
   - MMDB recovery tolerates structural tail truncation (with zero padding) **only** on the highest non-empty WAL and fails closed on checksum errors or any earlier WAL truncation ([db.rs](../../src/db.rs#L909-L970), [tests/crash_recovery.rs](../../tests/crash_recovery.rs#L706-L763)). Today synchronous flush keeps `WAL_new` empty until `MANIFEST` advances `log_number`; once background flush lets writers append to `WAL_new` immediately, rotating `WAL_old -> WAL_new` **must** seal (`flush()` + `sync_data()`) `WAL_old` before any byte reaches `WAL_new`.
   - **Lock & latency discipline:** Run `WAL_new` creation + `sync_parent_dir` and `WAL_old.sync_data()` **under `leader_active` outside `inner.lock()`** (taking `inner.lock()` only briefly to swap `(active_memtable, wal_writer)` and install the new `SuperVersion`) so background flush and compaction installs never block on WAL rotation I/O. Add `DbOptions::wal_bytes_per_sync: u64` (e.g., `2 MiB` default via periodic Linux `sync_file_range` / background writeback hints) so sealing `WAL_old` flushes only the trailing delta instead of spiking p99 latency on 64 MiB of accumulated `WalAsync` dirty pages.
   - **Seal fsyncgate:** If `WAL_old` flush/sync or `WAL_new` creation fails, poison the WAL writer, call `set_bg_error`, keep `WAL_old` in place (never publishing `WAL_new`), and fail subsequent writes/flushes closed.
2. **Fixing the latent `immutable_memtables` order bug & bounding multi-WAL recovery:**
   - **Present latent bug in `v4.3`:** [`freeze_memtable_sync`](../../src/db.rs#L3837) appends via `inner.immutable_memtables.push(old_mem)` (**oldest-first**), whereas [`DB::get_with_options`](../../src/db.rs#L1740-L1750) iterates front-to-back assuming `// 2. Immutable MemTables (newest first)` — harmless today only because synchronous flush caps queue depth at `1`! Store `immutable_memtables: VecDeque<Arc<MemTable>>`: `freeze` calls `push_front` (front-to-back = newest-first for point reads), while a **dedicated background flush thread** (isolated from compaction workers so L0 compaction stalls can never deadlock memtable flushes) flushes `back()` (oldest-first FIFO).
   - **Bounded multi-WAL crash recovery:** Recovery currently replays all residual `*.wal >= log_number` into a single memtable ([db.rs](../../src/db.rs#L923-L974)). With up to `max_immutable_memtables + 1` uncompacted WALs, stream-flush the recovery memtable whenever replayed bytes cross `write_buffer_size` (advancing `MANIFEST` `log_number` only after a WAL's final record is durably flushed) so recovery RSS stays bounded near `write_buffer_size`.
3. **v5 async-flush requirements: backpressure, generation-gated `flush()`, & fail-stop `close()`:**
   - *(In `v4.3`, synchronous flush holds `leader_active` through `confirm_manifest_durable` and blocks post-error writes, so these windows arise specifically when v5 decouples background flush from foreground writes.)*
   - When `immutable_memtables.len() >= max_immutable_memtables`, `WriteOptions::no_slowdown` returns `Err(ErrorKind::Busy)` (or `TryAgain`) immediately, while normal writers wait on `flush_cv` (woken on flush completion or `bg_error`).
   - Retain a frozen memtable in `immutable_memtables` (and hold its `flush_gen: u64` incomplete) until **both** `install_flush` **and** `confirm_manifest_durable` succeed ([db.rs](../../src/db.rs#L3946-L3995)).
   - If the oldest flush or its `MANIFEST` sync fails, set `bg_error`, wake all waiting writers/`flush()`/`close()`, and **forbid any later flush from installing or advancing `MANIFEST` `log_number` past the failed WAL** — updating [`DB::close`](../../src/db.rs#L3142-L3147) to check `fail_stop_error()` *before* freezing/flushing `active_memtable`.
4. **Full-level unlocked `force_merge_level` / sweeps & preserved `fsyncgate`:**
   - Today `compact()` / `compact_range()` hold `write_queue` ([db.rs](../../src/db.rs#L2635-L2670)), and **both** [`force_compact_all`](../../src/db.rs#L4186-L4220) and [`sweep_dead_keys_at_level`](../../src/db.rs#L273-L291) run `force_merge_level` I/O **under `inner.lock()`** — blocking writers on `inner` even if `write_queue` were dropped!
   - Refactor `force_merge_level` across **both L0 and L1+** into `pick (under inner.lock(), marking input files compacting) -> unlocked SST build & sync -> atomic install (under inner.lock())`, replacing `write_queue` holds with a `closing`-gated `active_maintenance_ops` counter + condvar drained by `close()`.
   - **Stale-input, snapshot, & L0 ordering guards:** Install verifies input files remain current, checks `output.filter_mutated && !snapshot_list.is_empty()` ([compaction/leveled.rs](../../src/compaction/leveled.rs#L1299), [db.rs](../../src/db.rs#L2806)), and for L0 rewrites ([db.rs](../../src/db.rs#L266-L282)) records `l0_install_epoch: u64` (incremented on every memtable freeze and L0 flush install), picking only when `immutable_memtables.is_empty()` and discarding/falling back to organic L0→L1 compaction if `l0_install_epoch` advanced during unlocked I/O (so sustained writes cannot invert L0 file order or starve dead-key reclamation).
   - **Unlocked parent-dir fsync with `fsyncgate` preserved:** Move SST parent-directory `fsync_directory` out of `VersionSet::log_and_apply` ([manifest/version_set.rs](../../src/manifest/version_set.rs#L562-L575)) into a mandatory `sync_new_sst_parent_dir` step at the end of every unlocked SST-producing path (flush, compaction, `force_merge_level`, recovery flush), passing a `DirSynced` token into `log_and_apply` and preserving poison/fail-stop on directory-sync error.
5. **Distinct `WalWriter::sync_data()` for WAL appends:**
   - Add `WalWriter::sync_data()` (`BufWriter::flush()` + `File::sync_data()`) for WAL append and rotation commits (whose parent directory entry was synced on creation), keeping `WalWriter::sync()` (`File::sync_all()`) for `open_append_truncated` truncation and `MANIFEST` syncs.

## 6. `MANIFEST` v2 and SST v2 on-disk formats

Source: [types.rs](../../src/types.rs#L46-L75), [sst/block.rs](../../src/sst/block.rs#L80), [sst/filter.rs](../../src/sst/filter.rs), [sst/format.rs](../../src/sst/format.rs), [sst/table_builder.rs](../../src/sst/table_builder.rs#L284-L545), [sst/table_reader/mod.rs](../../src/sst/table_reader/mod.rs#L39), [manifest/version_set.rs](../../src/manifest/version_set.rs#L168-L193), [audit.md](../audit.md#L21-L35).

### v5 wire specifications (`MANIFEST` v2 `DBHeader`, `TABLE_MAGIC_V2`)

1. **Crash-atomic `MANIFEST` `DBHeader` (`format_version = 5`, exact `num_levels` `2..=16`, `prefix_len: u32`) — landed first as the v5 format gate:**
   - Fix [`VersionSet::create_with_cache`](../../src/manifest/version_set.rs#L168-L193) to write and `sync_manifest()` the initial snapshot edit containing `DBHeader` **before** `set_current_file` publishes `CURRENT` (harmless in `v4.3` where an empty `MANIFEST` replays as empty, but mandatory once `DBHeader` is required so an interrupted create never leaves `CURRENT` pointing at a headerless `MANIFEST`).
   - Require `DBHeader` as the first record of every `MANIFEST` (including rotated snapshots), validate `2 <= num_levels <= 16` and `u32::try_from(prefix_len)` **before** allocating `Version` level vectors or truncating `MANIFEST`, adopt persisted `(num_levels, prefix_len)` automatically in `open_read_only` (closing the unpersisted `num_levels` gap at [src/lib.rs](../../src/lib.rs#L34-L35) / [audit.md](../audit.md#L31-L35); SSTs already persist per-file `filter.prefix_len` at [table_reader/mod.rs](../../src/sst/table_reader/mod.rs#L626), so `DBHeader.prefix_len` unifies store-level config validation), and require exact `num_levels` match on writable `DB::open`.
   - Fix 32-bit `(num_restarts as usize) * 4 + 4` overflow via `checked_mul` at [sst/block.rs](../../src/sst/block.rs#L80) ([audit.md](../audit.md#L21-L24)).
2. **Aligned 64-byte cache-line-blocked Bloom filter (`FILTER_FORMAT_BLOCKED_64B = 2`):**
   - Change `DbOptions::default().bloom_bits_per_key` from `10` ([options.rs](../../src/options.rs#L140)) to **`12`** (+20% filter bytes) and identify the new layout via metaindex `filter.format = 2`, hashed with **XXH3-64 (`seed = 0`)** and pinned cross-platform test vectors for both key and prefix filters.
   - Because `write_raw_block` may LZ4/Zstd-compress filter blocks on disk ([sst/table_builder.rs](../../src/sst/table_builder.rs#L499-L545)), `TableReader::open` decompresses/copies the filter payload into an owned 64-byte-aligned `AlignedBytes` (`#[repr(align(64))]`, 512 bits/line; filter blocks live on `TableReader`, not `BlockCache`).
   - One 64-bit hash `h` selects the 64B line via 64-bit Lemire fastrange `(((h >> 32) as u64 * (num_lines as u64)) >> 32) as usize` (`1 <= num_lines <= u32::MAX`) and probes `k = 8` bits starting at `(h as u32) & 511` with odd step `((h as u32).rotate_left(15)) | 1` (`gcd(odd, 512) == 1` — 1 cache line per probe; 512-bit Poisson floor under independent uniform probes is **~0.41% (`0.407%`) at 12 bpk, $k = 8$**, while the 1D 32-bit affine progression `start + i * step (mod 512)` yields **~0.57% (`0.566%` analytical, `0.59%` empirical)** vs ~0.82% / `0.86%` empirical for `v4.3` standard 10 bpk, $k = 7$; see §7.1–§7.2 for the exact derivation and level-proportional Monkey budgeting).
3. **Valid `InternalKey` shortest separators + independent-restart partitioned index:**
   - **Exact internal-key separator:** When closing data block `i` (`last_ikey`) before `next_first_ikey` with `last_uk < next_first_uk`, construct any shortened prefix `s` (`last_uk < s < next_first_uk`) via **`InternalKey::new(s, MAX_SEQUENCE_NUMBER, ValueType::RangeDeletion)`** — whose inverted trailer is `[0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0xFD]`, the smallest valid internal key for user key `s` (`[0x00; 8]` decodes as invalid `value_type = 255` and fails [`decode_internal_key`](../../src/types.rs#L207-L226)!). Keep `last_ikey` un-shortened when `last_uk == next_first_uk` and on the final **point** block of the SST (separating final point-index boundary from `FileMetaData.largest_key`, which may come from a range tombstone at [table_builder.rs](../../src/sst/table_builder.rs#L284-L302)), and update `IndexEntry` docs ([table_reader/mod.rs](../../src/sst/table_reader/mod.rs#L39)).
   - **Two-level partitioned index:** Split index entries into ~64 KiB leaf index blocks (allowing single oversized entries up to `MAX_DECOMPRESSED_BLOCK_SIZE` for 8 MiB keys), each starting with a **self-contained full key** and read via `BlockCache` (`fill_cache = false` during compaction). Retain `first_key` inside leaf entries for zero-I/O deferred `TableIterator::seek`, drop duplicate raw root `Block` bytes once `TableReader` parses the compact top-level partition array, and enforce per-memtable/batch same-key metadata admission accounting so million-version 8 MiB single-key floods fail fast at write admission rather than at flush/recovery ([audit.md](../audit.md#L26-L30)).
4. **Pre-fragmented, clipped, overlap-free partitioned range-deletion blocks:**
   - Partitioning raw overlapping tombstones (`[a, z)@10` in leaf 0, `[m, n)@11` in leaf 1) by `begin_key` alone would miss `[a, z)@10` when probing `y`!
   - Instead, capture active `SnapshotList` stripes at **both** flush and compaction start (extending compaction's snapshot capture at [db.rs](../../src/db.rs#L2718-L2721) to memtable flush), **fragment range tombstones at SST build time into disjoint elementary intervals `[begin_i, end_i)` (`end_i <= begin_{i+1}`)** retaining at most one newest sequence per snapshot stripe, **clip spanning intervals at SST output-file split boundaries `K_split`**, and partition those disjoint intervals across ~64 KiB `rangedel` leaf blocks (allowing single oversized interval leaves up to `MAX_DECOMPRESSED_BLOCK_SIZE` and accounting `O(T · S)` fragment × snapshot growth so outputs split cleanly across SSTs on interval boundaries) indexed by `max_end_key`. Any point probe `y` binary-searches `first partition with max_end_key > y` and reads **at most one** `rangedel` leaf block!

## Preserved invariants, migration, and staged rollout

- **Exact engine invariants:**
  - `ArcSwap<SuperVersion>` point reads avoid `DB::inner` (active-memtable range-tombstone checks take a short `RwLock` read guard and first frozen lookup initializes `OnceLock` segment tree);
  - WAL-before-MemTable publication holds for `WalAsync` and `WalSync` (`DisableWal` opts out explicitly);
  - WAL recovery tolerates structural tail truncation (with zero padding) **only** on the highest non-empty WAL and fails closed on checksum corruption or any earlier WAL truncation;
  - `LOCK` is acquired (`LOCK_EX` writable, `LOCK_SH` read-only when `LOCK` exists; **zero write-intent syscalls** on unlocked immutable read-only snapshots when `LOCK` is absent per [read-only-mode.md](read-only-mode.md#L18-L29), [L137-L158](read-only-mode.md#L137-L158)) **before** reading `CURRENT`/`MANIFEST`, and a format mismatch fails closed immediately after `LOCK` without modifying `CURRENT`, `MANIFEST`, WAL, or SST bytes (`open_read_only` performs zero write-intent syscalls on mismatch).
- **Migration & staged rollout sequence (`DBHeader` format gate landed first):**
  1. **Stage 0 — `v4.x` pre-work, golden v4 fixtures, & exporter:** Fix `v4.x`-safe buglets (`immutable_memtables` two-generation order test/fix, `#[must_use]` on `Snapshot`, `need_sync |= r.sync && !r.disable_wal`); capture golden v4 fixtures (residual WAL with puts/deletes/range-deletes, non-default `num_levels`/`prefix_len`, multi-snapshot crossing range tombstones); and ship a version-pinned v4 exporter checking `.error()` on completion (`vsdb` v18 uses its logical exporter for `VerMap`/`DagMap`/`SlotDex` fidelity; optionally retain read-only `TABLE_MAGIC_V1` / headerless-`MANIFEST` inspection if low-complexity while keeping writable v5 strictly v5-formatted).
  2. **Stage 1 — Crash-atomic `MANIFEST` `DBHeader` (`format_version = 5`) & public MVCC/API contracts:** Land crash-atomic `create_with_cache` + `DBHeader` (`format_version = 5`, `num_levels` `2..=16`, `prefix_len`) **first** so all subsequent wire changes sit behind an explicit version gate; plus `#[non_exhaustive]` option builders, `Cow<'a, [u8]>` `ReadOptions<'a>` + `SnapshotRef<'a>`/`ArcSnapshot`, `DurabilityMode`, key-only + post-MVCC `BlockPropertyCollector`/`Filter`, `Option<&Error>` + strict-precedence `step_next`/`step_prev`, and `DB::contains_key`.
  3. **Stage 2 — Vectored flat `WriteBatch`, raw-slab `MemTable`, & `PinnedSlice`:** Land v4-WAL-identical `WriteBatch` (`put_prefixed` family + `WalWriter::add_record_parts` zero-mutation group commit + `WBWI` `BTreeMap<Box<[u8]>, _>`), 8B-aligned raw-slab variable-height skiplist (pre-initialized towers, `>256 KiB` dedicated slabs, `MAX_WRITE_BATCH_GROUP_BYTES` cap, standalone Miri concurrency suite), and `DB::get_pinned`.
  4. **Stage 3 — Leader-unlocked sealed-WAL FIFO flush, `sync_wal`, & unlocked sweeps:** Land leader-unlocked WAL rotation (`wal_bytes_per_sync` smoothing + seal fail-stop), `VecDeque` newest-first/oldest-first `max_immutable_memtables` FIFO with dedicated flush worker + bounded multi-WAL recovery, generation-gated `flush()` + fail-stop-first `close()`, `DB::sync_wal`, `WalWriter::sync_data()`, and full-level unlocked `force_merge_level` (L0 `l0_install_epoch` + L1+ stale-input/snapshot checks + `sync_new_sst_parent_dir` `fsyncgate`) — gated on two-generation visibility tests, seal/flush/`MANIFEST` fault injection, unsynced-page-cache power-loss tests beyond `simulate_crash`, L0 flush-vs-sweep race tests, and write p99/p999 across WAL rotation & `max_immutable_memtables` backpressure benchmarks.
  5. **Stage 4 — SST v2 (`TABLE_MAGIC_V2`) under `format_version = 5`:** Land 64B-aligned XXH3-64 blocked Bloom filters (`filter.format = 2`), `[0x00..0xFD]` shortest separators + independent-restart partitioned index, pre-fragmented boundary-clipped partitioned `rangedel` blocks, and 32-bit `checked_mul` restart validation — gated on crossing-tombstone snapshot/split-clipping tests, 8 MiB same-key + high-snapshot tombstone admission/flush tests, empirical Bloom FPR verification, and multi-threaded read/write p99 & RSS benchmarks.

#### B. Blocked Bloom mathematical & multi-level audit

1. **Why 12 bpk measured `0.59%` instead of `0.41%` — and the `65,536`-pattern high-`bpk` floor:**
   - An unblocked Bloom filter at $b = 12$ bpk, $k = 8$ achieves $(1 - e^{-8/12})^8 = \mathbf{0.314\%}$.
   - Partitioning into $B = 512$-bit (`64 B`) cache lines introduces Poisson load variance ($\lambda = 512 / 12 = 42.67$ keys/line): with 8 **independent** uniform bit probes per line, $\sum_{c=0}^{\infty} \frac{e^{-\lambda}\lambda^c}{c!}\bigl(1 - (511/512)^{8c}\bigr)^8 = \mathbf{0.407\%}$.
   - However, [`probes`](../../src/sst/filter.rs#L36-L44) generates all 8 bit positions from a **1D 9-bit arithmetic progression** $\text{bit}_i = (\text{low} + i \cdot \text{step}) \bmod 512$ where `low & 511` (`512` starts) and `(low.rotate_left(15) | 1) & 511` (`256` odd steps) form `131,072` `(start, step)` pairs, and every 8-term progression equals its own reversal `(start + 7*step, 512 - step) mod 512`—leaving **only `65,536` distinct 8-bit masks per cache line**.
   - At $12.0\text{ bpk}$, affine correlation raises exact/Monte-Carlo FPR from `0.407%` to **`0.566%`** (`0.568%` MC / `0.59%` empirical on 200k SST keys — a **+39% relative FPR penalty**). At higher `bpk`, single-key exact-mask collisions ($\approx c / 65536$) plus 2-key sub-progression cover create a steep floor: at `16 / 20 / 24 bpk`, `filter.format = 2` achieves **`0.192%` / `0.102%` / `0.067%`** vs **`0.087%` / `0.025%` / `0.009%`** under independent 512-bit probes (`7.7×` gap at `24 bpk`).
2. **Uniform vs. level-proportional (Monkey) multi-level FPR:**
   - In a leveled LSM ($R = 10$, 4 L0 SSTs + `L1..L4`), ~90% of keys live in bottommost `L4` (`~90%` of resident `AlignedBytes` RAM), yet an absent-key lookup probes **8 SST filters** (`4` in L0 + `1` per `L1..L4`), suffering `8 × 0.568% ≈ 4.55%` (`3.26%` at the `0.407%` independent Poisson floor) cumulative false-positive rate per `DB::get` miss.
   - Reallocating the **same `~11.7–11.9 bpk` weighted memory budget** across levels cuts cumulative 8-SST false positives from **`4.55% → 1.33–1.39%` (`~3.3–3.4×` reduction)** on unchanged `filter.format = 2` (diminishing above `16–20 bpk` due to the 65,536-mask floor), and down to **`0.69–0.75%` (`~6.1–6.6×` vs uniform `v5.0`, or `~4.3–4.8×` vs uniform independent `3.26%`)** when paired with independent intra-line probes (`filter.format = 3`).

#### C. `BlockCachePool` segment-capacity cliff on oversized blocks

[`BlockCachePool::new`](../../src/cache/block_cache.rs#L64-L80) ([L182-L193](../../src/cache/block_cache.rs#L182-L193)) partitions a default `64 MiB` moka W-TinyLFU cache into `64` `SegmentedCache` shards (`1 MiB` max capacity per shard, weighed by `Vec::capacity()`). Any unpinned block whose buffer exceeds `1 MiB` (`1 MiB < capacity <= 64 MiB`, such as data blocks holding large inline values, `block_size > 1 MiB`, or multi-hundred-KiB-key index/`rangedel` leaves exceeding `PARTITION_BYTES = 64 KiB`) exceeds its single segment's `1 MiB` limit and is **evicted immediately upon admission** despite `63 MiB` of free pool capacity.

### 7.2 Concrete `v5.x` structural optimization designs

The six designs below (`P1`–`P6`) address the bottlenecks identified in §7.1. **`P1`–`P3`, `P4.1` (zero-length standby WAL), and `P5` are now implemented in `v5.0.0`** (including independent SplitMix64 intra-line 64B Bloom probing directly in `filter.format = 2` prior to tagging `v5.0.0`); optional high-concurrency write-pipeline extensions (`P4.2`/`P4.3`) and large-value blob separation (`P6`) remain deferred opt-in designs.

| ID | Target bottleneck | Core structural change | Expected impact | Status |
|---|---|---|---|---|
| **P1** | `+32.7%` SST `get` regression, `63.8 µs` `seek`, `>1 MiB` segment cliff | Validated-on-fill `IndexLeaf` / `Block` caching + zero-parse `TableIterator` restart cursor + `BlockCachePool` unsegmented `>1 MiB` overflow | Eliminates `~3N` heap allocs/seek & `O(N)` `Block::new` restart scans on `get`/`seek` | **Implemented** |
| **P2** | Per-row `Vec` allocs in `step_next`, `MemTable` `v.to_vec()`, & backward `prev` | Key-buffer ping-pong (`take_entry_into`), in-place `MemTablePin` / `BlockRef` reuse, two-phase skip peek (`advance_key`), arena-backed reverse window | **`0` heap allocs/row** in steady-state `step_next`; `0` value copies on skipped/lending MemTable & reverse SST scans | **Implemented** |
| **P3** | `~4.55%` cumulative multi-level Bloom FPR & `L_max` RAM dominance | Independent 8-probe SplitMix64 64B Bloom (`filter.format = 2`) + Monkey level-proportional `bits_per_key` (`<= 24`) + `DbOptions::optimize_filters_for_hits` | **`~6.5×` fewer** false-positive SST reads at lower total RAM, or **`-85–90%` point-filter RAM** on hit-heavy stores | **Implemented** |
| **P4** | WAL rotation `p999` & multi-writer leader serialization | Zero-length pre-created standby WAL (`P4.1`, **implemented**); optional drain-fenced 2-stage WAL/MemTable pipeline & CAS skiplist splice (`P4.2`/`P4.3`) | Removes `File::create` + dir-`fsync` from rotation leader; optional multi-writer WAL/MemTable overlap | **P4.1 Implemented** (`P4.2`/`P4.3` deferred) |
| **P5** | `mmdb-v4-export` / bulk restore `3–5×` WA & per-key syscalls | `DB::ingest_sorted` streaming `target_file_size_base` SSTs to `L_max` + `mmdb-v4-export` integration | **`1.0×` write amplification**, `0` WAL bytes, `~5–10×` faster v4→v5 migration & snapshot import | **Implemented** |
| **P6** | `5–10×` compaction WA & cache pollution on values `>= 4 KiB` | Key-value separation (`BlobFile` + `ValueType::BlobIndex` + `Version`-tracked compaction GC) | Cuts large-value compaction I/O by `5–10×` and keeps SST data blocks dense in `BlockCache` | **Deferred** (`v5.x` opt-in or `v6`) |

**Recommended execution order:**
1. **Immediate low-risk internal & tooling wins:** Land **P1** (cache-fill `Block` validation + zero-parse `TableIterator` index cursor), **P2** (zero-alloc lending cursor + `MemTable` slice borrowing), and batched `DisableWal` `WriteBatch`es in [`mmdb-v4-export`](../../tools/v4-export/src/main.rs#L39-L66).
2. **Profiled runtime, filter, & bulk-ingest upgrades:** Profile `freeze_memtable` (`old_wal.sync_data()` vs `File::create` + `sync_parent_dir()`) and land **P4.3**'s zero-length standby WAL; decide whether to pair **P3** with `filter.format = 3` or ship `<= 16–20 bpk` upper-level budgets on `filter.format = 2`; land **P5** (`DB::ingest_sorted`) with full MVCC/tombstone preconditions if external callers (`vsdb`) need programmatic bulk import.
3. **High-concurrency / large-value follow-ups:** Prototype **P4.1/P4.2** (pipelined group commit + concurrent CAS skiplist splicing under expanded Miri coverage) only if multi-writer benchmarks remain bottlenecked after P4.3, and keep **P6** deferred unless targeting `>= 4 KiB` value workloads.

#### P1. Validated `IndexLeaf` caching, zero-parse `TableIterator` cursor, & `BlockCachePool` tuning

1. **Validate `Block` restarts and index ordering once at cache-fill time (fixing both `get` and `seek`):**
   - On warm `DB::get`, `find_data_block` ([table_reader/mod.rs](../../src/sst/table_reader/mod.rs#L660-L673)) already binary-searches in place via `Block::seek_by_reuse` ([block.rs](../../src/sst/block.rs#L168-L215)) without heap allocation, **but** [`Block::new`](../../src/sst/block.rs#L91-L108) walks **all `num_restarts` offsets linearly (`O(N)`)** on every call (`~650–850` checks per `64 KiB` `restart_interval = 1` index leaf, plus `~16` on the data block)!
   - Validate `Block` restart monotonicity (`restart_offset`, `num_restarts`, strictly ascending offsets) **once** when a block is read/admitted into `BlockCachePool` (storing `(Arc<Vec<u8>>, restart_offset, num_restarts)` or a validated `CacheValue`), reducing `Block` construction on cache hits to `O(1)`.
   - For index leaves specifically, also run the full one-time structural & ordering validation (`first_key <= separator_key < next.first_key` across all entries, currently performed repeatedly in [`parse_index_entries`](../../src/sst/table_reader/mod.rs#L356-L370), plus partition boundary checks `entry(0).first_key > partitions[part - 1].0` and `entry(last).separator_key == partitions[part].0`) **once** on leaf cache admission rather than weakening corruption detection to `O(1)` boundary-only checks or repeating it on every iterator open.
2. **Exploiting `restart_interval = 1` in `TableIterator` (`0` allocations on iterator open/seek):**
   - [`IndexWriter::new` / `flush_leaf`](../../src/sst/table_builder.rs#L184-L226) writes every index leaf with `BlockBuilder::new(1)` (`restart_interval = 1`), so every index entry `j in 0..N` has **`shared_len == 0`** and its exact byte offset at `restarts[j]`.
   - **Eliminate `IndexEntry` / `parse_index_entries` from `TableIterator`:** Replace `TableIterator::index_entries: Option<Arc<Vec<IndexEntry>>>` ([table_reader/iterator.rs](../../src/sst/table_reader/iterator.rs#L31)) with a validated `index_block: Option<Block>`.
   - **Direct `O(log N)` in-place binary search:** Compare entry `j` against `target` directly at `offset = block.restart_point(j)` (`shared == 0`, `&data[key_start..key_end]` vs `target` in place, zero key copies and zero trailing linear scan since `restart_interval = 1`), and decode `DecodedIndexValue<'a>` (`handle`, borrowed `first_key: &'a [u8]`, and borrowed property slices for `BlockPropertyFilter::should_skip`) **only** for the selected entry `idx` without allocating `Vec<(Vec<u8>, Vec<u8>)>`.
3. **Budget-preserving metadata caching & `BlockCachePool` segment sizing:**
   - **Leaf geometry & strict cache accounting:** At default `block_size = 4 KiB` and `PARTITION_BYTES = 64 KiB` (`~75–90 B`/index entry → `~650–850` entries/leaf, covering `~2.6–3.4 MiB` of data blocks), SSTs `<= ~3 MiB` (`sst_10k`, `sst_2k`) have `1` index leaf, while a full `64 MiB` SST has **`~20–25` index leaves** (`~1.3–1.6 MiB`). Storing unbudgeted `OnceLock<Block>` slots on `TableReader` would leak index memory outside `block_cache_capacity` and undo SST v2's bounded-RAM guarantee. Instead:
     - Keep all cached index/`rangedel` leaves **strictly accounted inside `BlockCachePool`** (save for explicitly bounded L0 pins when `pin_l0_first_block_and_warm_index` is enabled); measure actual index-leaf hit ratios under scan-mixed workloads before adding a dedicated high-priority metadata pool share (e.g., `DbOptions::cache_index_and_filter_blocks_with_high_priority: bool`) on top of moka's existing W-TinyLFU frequency admission.
     - Add a regression test inserting a `2 MiB` block into a `64 MiB` `BlockCachePool` and fix the `1 MiB` segment-capacity cliff ([cache/block_cache.rs](../../src/cache/block_cache.rs#L64-L80)) by routing blocks with `weight > segment_capacity` to an unsegmented overflow cache (still bounded within total pool capacity) or scaling `MIN_LRU_SEGMENT_CAPACITY` for larger pools.

#### P2. True zero-allocation lending cursor (`step_next` / `step_prev`) & `MemTable` slice streaming

1. **Key-buffer ping-pong (`MergingIterator::take_entry_into`):**
   - Add `MergingIterator::take_entry_into(&mut self, key_out: &mut Vec<u8>, val_out: &mut LazyValue) -> bool`: instead of `std::mem::take(&mut source.peeked_key)` ([iterator/source.rs](../../src/iterator/source.rs#L206-L220), which leaves a `0`-capacity `Vec` behind and forces a fresh heap allocation on `source.peek()`), **`std::mem::swap(key_out, &mut source.peeked_key)`** recycles `DBIterator`'s previous `current_key` buffer directly into `source.peeked_key` before `source.peek()` overwrites it in place.
   - Avoid copying `MergingIterator::current_key` on every forward `take_entry_into` while preserving [`MergingIterator::seek_opt`](../../src/iterator/merge.rs#L373-L384)'s 4-step `try_next` fast path (called by [`DBIterator`](../../src/iterator/db_iter.rs#L268), [L613](../../src/iterator/db_iter.rs#L613)) by passing `prev_key: Option<&[u8]>` from `DBIterator`'s already-retained key buffer (`current` / `last_user_key`) into `seek_opt` and direction-switch helpers.
2. **Zero-copy `MemTableCursorIter` & two-phase skip peeking:**
   - `DBIterator` already uses `advance_entry()` ([iterator/db_iter.rs](../../src/iterator/db_iter.rs#L289-L290)) to skip shadowed/deleted versions without `take_entry()`, **but** [`IterSource::advance_into_buffers`](../../src/iterator/source.rs#L247-L268) still calls `next_lazy` on every peeked row, where [`MemTableCursorIter::next_lazy`](../../src/memtable/skiplist.rs#L224-L247) allocates `LazyValue::Inline(v.to_vec())`.
   - Split `IterSource` peeking into **two phases** (`peek_key` vs `materialize_value`) so heap comparisons and skipped MVCC versions touch only `peeked_key` (zero `v.to_vec()` and zero `Block` `Arc::clone` on skipped entries).
   - For visible MemTable rows on lending `step_next`, borrow the immutable arena value bytes directly from `MemTableCursorIter`'s existing `self.memtable: Arc<MemTable>` ([memtable/skiplist.rs](../../src/memtable/skiplist.rs#L103-L106), which stays alive for the iterator's lifetime) without per-row `Arc::clone` refcount traffic across cores—materializing an `Arc`-cloned `LazyValue::MemTable(MemTablePin)` only if an owned/detached `PinnedSlice` outlives the cursor step.
3. **Zero-copy backward `TableIterator` restart window:**
   - Replace `TableIterator::current_block_entries: Vec<(Vec<u8>, Vec<u8>)>` ([table_reader/iterator.rs](../../src/sst/table_reader/iterator.rs#L60)) with a compact window `Vec<RestartEntry>` storing `(key_buf_range: (u32, u32), val_offset: u32, val_len: u32)` packed into one reusable `backward_keys_arena: Vec<u8>` on `TableIterator` and borrowing `backward_block.data_arc()` (`LazyValue::BlockRef`). Reverse scans (`step_prev` / `next_back`) then allocate **0 `Vec`s per restart segment** and copy **0 value bytes** on skipped entries.

#### P3. Level-proportional blocked Bloom budgeting (Monkey) & hit-optimized bottommost elision

1. **Per-level `bits_per_key` allocation (`100%` wire-compatible with `filter.format = 2`):**
   - [`AlignedBytes::decode`](../../src/sst/filter.rs#L13-L26) derives `num_lines = bytes.len() / 64` per SST without reading `DbOptions::bloom_bits_per_key`. Thus `FlushContext::flush` and `LeveledCompaction` can size each output SST's filter according to its target level $L$ with **zero reader or format changes**.
   - **Schedule & `filter.format = 2` diminishing-returns bound:** Under `filter.format = 2` ($k = 8$ fixed affine probes in [`probes`](../../src/sst/filter.rs#L36-L44)), single-file FPR drops from `0.568%` (`12 bpk`) to **`0.192%` (`16 bpk`)**, **`0.102%` (`20 bpk`)**, and **`0.067%` (`24 bpk`)**—flattening above `16–20 bpk` due to the `65,536`-mask progression floor (§7.1.B). Using the Monkey step $\Delta = \frac{\ln R}{\ln^2 2}$ ($4.79$ for $R = 10.0$) with cap $b_{\max} = 20$ on `filter.format = 2` (or $24$ on `filter.format = 3`):
     $$b_L = \text{clamp}\!\left(\left\lceil \bar{b} + \frac{\ln R}{\ln^2 2}\,(L_{\text{bottom}} - L) \right\rceil,\; \bar{b},\; b_{\max}\right), \qquad b_{L_{\text{bottom}}} = \max(8, \bar{b} - 1)$$
     (giving `[20, 20, 20, 17, 11]` capped at `20` or `[24, 24, 22, 17, 11]` capped at `24` for $\bar{b} = 12, R = 10, L_{\text{bottom}} = 4$, weighted `~11.5–11.7 bpk`), cumulative 8-SST false positives drop by **`~3.3–3.4×`** (`4.55% → 1.33–1.39%`) at identical or lower total RAM.
   - **Engine invariants to preserve:**
     - **Size cap:** Clamp effective $b_L$ per SST via `BloomFilter::checked_size` so high-key-count SSTs never exceed `META_BLOCK_HARD_LIMIT`; keep `filter.prefix` ([table_builder.rs](../../src/sst/table_builder.rs#L353)) at configured `bloom_bits_per_key` (or identically clamped).
     - **Trivial moves & dynamic tree depth:** Trivial moves ([compaction/leveled.rs](../../src/compaction/leveled.rs#L1058)) retain their source level's filter until compacted. Compute $b_{L_{\text{bottom}}}$ (and optional `DbOptions::optimize_filters_for_hits: bool`, default `false`, which omits `filter.bloom` on bottommost SSTs—already supported by `MetaIndexData::bloom: Option<Vec<u8>>`—to save `~85–90%` filter RAM on hit-heavy `vsdb` tries) only at structural `level == num_levels - 1` (or rebuild when a dynamically deepest level compacts downward) so growing trees never strand filterless SSTs in intermediate levels.
2. **Co-designed `filter.format = 3` option (register-split independent probing):**
   - Because `filter.format = 2`'s `65,536`-mask floor sacrifices `7.7×` of the upper-level FPR win at `24 bpk` (`0.067%` vs `0.009%`), introducing `filter.format = 3`—deriving 8 independent 9-bit indices from two 64-bit mixes (`h1 = mix64(h)`, `h2 = mix64(h ^ K)` → `8 × 9 = 72` independent bits within one 64B cache line)—recovers the full `0.407%` 12-bpk Poisson floor and **`~6.1–6.6×` cumulative multi-level FPR reduction** (`4.55% → 0.69–0.75%`) at identical byte size and 1 cache-line touch. Decide whether to gate `filter.format = 3` alongside P3 before tuning upper-level `bpk` above `16–20`.

#### P4. Zero-length standby WAL rotation & concurrent write-pipeline follow-ups

1. **Asynchronous pre-created zero-length standby WAL (sound fix for rotation `File::create` + dir-`fsync`):**
   - **First step — profile `freeze_memtable` ([db.rs](../../src/db.rs#L3242-L3277)):** Measure the exact split of the `~4.9 ms` `v5_profile` write `p999` between `old_wal.sync_data()` (already smoothed by `wal_bytes_per_sync = 2 MiB`) and `WalWriter::new` (`File::create` + `sync_parent_dir()`).
   - **Why both WAL recycling and `posix_fallocate` break MMDB recovery:**
     1. Reusing an unzeroed old `.wal` breaks `W5` ([`WalReader::rest_is_zero_padding`](../../src/wal/reader.rs#L71-L85)).
     2. Preallocating `{standby_num:06}.wal` via `posix_fallocate` up to `write_buffer_size` sets `meta.len() > 0` on disk—which **hijacks `recoverable_tail_wal_num`** ([db.rs](../../src/db.rs#L1048-L1061), causing a crash mid-append on the real active WAL to fail open!), leaves trailing `0x00` bytes in sealed WALs that trip [`zero-extended WAL header`](../../src/wal/reader.rs#L337-L353) fail-closed corruption unless truncated + metadata-synced at seal, and **still** journals unwritten-to-written extent conversions during `fdatasync` on ext4/XFS.
   - **Sound design (`0`-byte standby WAL):** Have `mmdb-flush` (or a post-rotation helper) pre-create a **zero-length (`0 B`)** `{standby_num:06}.wal` and call `sync_parent_dir()` **ahead of rotation** without `fallocate`:
     - On rotation, `freeze_memtable` runs `old_wal.sync_data()` and swaps in the pre-opened standby `WalWriter` in `O(1)` with **zero `File::create` or directory `fsync` on the leader**.
     - On crash, `meta.len() == 0` preserves `recoverable_tail_wal_num` on the real active WAL ([db.rs](../../src/db.rs#L1048-L1061), [L1100-L1101](../../src/db.rs#L1100-L1101)), and writable recovery advances `file_numbers` / `log_number` past `max_disk_file_number` ([db.rs](../../src/db.rs#L1045), [L1158](../../src/db.rs#L1158)) before [`remove_orphan_files`](../../src/db.rs#L1176) ([L3536-L3540](../../src/db.rs#L3536-L3540)) unlinks the unused standby. On clean [`DB::close`](../../src/db.rs#L2655-L2710) (which does not run `remove_orphan_files`), explicitly drop and unlink any unused standby WAL so clean directories and `open_read_only` snapshots remain orphan-free.
2. **Optional two-stage pipelined group commit (multi-writer WAL/MemTable overlap):**
   - [`write_batch_group`](../../src/db.rs#L3029-L3201) currently holds `DB::inner` (`L3059`) across **both** vectored WAL I/O (`add_record_parts` + `flush`/`sync_data`) **and** sequential `MemTable::put` insertion (single-writer `fillseq` has no second group to overlap, so pipelining targets multi-thread write throughput).
   - Splitting into **Stage 1 (WAL Leader)** and **Stage 2 (MemTable Leader)** requires moving `wal_writer` out of `DB::inner` and enforcing three strict invariants:
     - **Rotation / flush / `close` drain barrier:** Whenever `active_memtable` reaches `write_buffer_size` (or `flush`, `close`, or `admit_same_key_runs` overflow triggers rotation), Stage 1 **must drain `memtable_queue`** before sealing `old_wal` and swapping `(active_memtable, wal_writer)` so records in `WAL_new` never enter `MemTable_old`.
     - **Pre-WAL validation:** Stage 1 validates sequence exhaustion (`<= MAX_SEQUENCE_NUMBER`) and admission caps *before* appending to WAL so Stage 2 `MemTable::put` cannot fail after group $G_{i+1}$ has already written WAL bytes.
     - **Monotonic visibility (`CC1`):** `DisableWal` and `WalFence` requests flow through the same Stage 1→Stage 2 sequence order so `committed_sequence` advances strictly in sequence order after MemTable insertion.
3. **Concurrent MemTable splicing vs. uncontended `Mutex<Arena>`:**
   - [`ConcurrentSkipList::insert`](../../src/memtable/skiplist_impl.rs#L134) ([L202-L245](../../src/memtable/skiplist_impl.rs#L202-L245)) holds `Mutex<Arena>` across `random_height`, [`Arena::allocate`](../../src/memtable/skiplist_impl.rs#L70-L103), `search`, and tower splicing, and is **completely uncontended** while a single MemTable leader inserts sequentially—so replacing `Arena::allocate` alone with an `AtomicUsize` CAS bump while keeping a splice mutex saves ~0 cycles.
   - Unlocking multi-core MemTable insert scaling (only warranted if multi-writer workloads saturate Stage 2 CPU) requires **concurrent lock-free CAS tower splicing** (followers allocating disjoint slices via per-thread slab chunks / CAS bump and CAS-linking level `0..height` pointers before leader `committed_sequence` publication), paired with expanded `tests/arena_miri.rs` Stacked/Tree Borrows schedules.

#### P5. Batched `DisableWal` migration & bottommost bulk ingestion (`DB::ingest_sorted`)

1. **Immediate zero-API win for `mmdb-v4-export`:**
   - [`mmdb-v4-export`](../../tools/v4-export/src/main.rs#L39-L66) streams `v4::DB` in ascending key order into an isolated temporary `staging` directory, calls `target.close()` (flushing to synced SSTs + synced `MANIFEST`), and atomically `rename`s `staging` + `sync_all`s the parent directory. Switching `target.put(&key, &value)` (`L52`) to `1–4 MiB` `WriteBatch`es with `DurabilityMode::DisableWal` immediately eliminates per-key allocations, `write()` syscalls, and `1×` WAL I/O with **zero engine changes**.
2. **Additive `DB::ingest_sorted` (`1.0×` WA for large migrations & external `vsdb` snapshot imports):**
   - Note that `vsdb` v18 uses its own logical exporter (§Preserved invariants, Stage 0), so `DB::ingest_sorted` benefits `vsdb` directly when exposed as `pub fn ingest_sorted<I, K, V>(&self, iter: I) -> Result<u64>`:
     1. **Target SST sizing:** Stream strictly ascending `(user_key, value)` pairs (`InvalidArgument` on out-of-order/duplicate keys or keys `> MAX_USER_KEY_SIZE`) into `TableBuilder` outputs split at **`target_file_size_base`** (`64 MiB`, matching [`LeveledCompaction`](../../src/compaction/leveled.rs#L713)—*not* `max_bytes_for_level_multiplier^(L_max - 1)`, which scales level capacity rather than file size and would overflow `META_BLOCK_HARD_LIMIT`), tracking `PendingSsts` for error/crash cleanup.
     2. **Full MVCC, range-tombstone, & `L_max` non-overlap preconditions:** Under `MaintenanceGuard` + `write_queue` barrier, verify that the ingested `[min_key, max_key]` span is strictly disjoint from **all** point entries and **range tombstones** in `active_memtable` / `immutable_memtables` and from **every** `[smallest, largest]` `FileMetaData` boundary across **`L0..L_max`** (preventing upper-level tombstones from shadowing `L_max` rows and preserving `L_max` non-overlap).
     3. **Snapshot-safe sequence assignment:** Use `seq = 0, ValueType::Value` **only** when the store is completely empty and `snapshot_list.is_empty()`; otherwise allocate a single fresh `ingest_seq` from `self.sequence` before building (publishing `committed_sequence` and `MANIFEST` `last_sequence = ingest_seq` on install) so pre-existing `Snapshot`s (`snapshot_seq < ingest_seq`) never observe post-snapshot ingested keys.
     4. **Atomic durable install:** `finish()` (`sync_all`) every SST → `sync_new_sst_parent_dir` (`DirSynced`) → install all files at `num_levels - 1` (`L_max`) in one `VersionEdit` + `confirm_manifest_durable`.

#### P6. Optional large-value separation (`BlobFile` / WiscKey threshold — deferred / opt-in)

- **Workload crossover analysis (aligning with [COMPARISON.md](../../COMPARISON.md#L107-L112)):**
  - For `< 4 KiB` values (`vsdb` slot metadata, B+ tree interior/leaf nodes, indexes), inline SST values + `PinnedSlice` (`LazyValue::BlockRef`) achieve optimal spatial locality (`1` `pread` for both point and range scans, zero blob GC).
  - For `>= 4–16 KiB` values (`bench_value_sizes/write/65536B`), inline storage rewrites full payloads across every compaction (`~5–10×` WA) and fills 4–64 KiB data blocks with 1 value each, polluting `BlockCache`.
- **Isolated opt-in architecture (when/if enabled via `DbOptions::blob_min_value_size: Option<usize>`):**
  1. **Format gate:** Gate behind `MANIFEST` `format_version = 6` (or an explicit `DBHeader` feature bit) so pure KV stores pay zero complexity.
  2. **Blob file & handle encoding:** Flush/compaction streams values `>= blob_min_value_size` into immutable CRC32-framed `{num:06}.blob` files (`[key_len | val_len | key | val | crc32]` + footer), writing a 24-byte `ValueType::BlobIndex` (`[blob_file_num: u64 | offset: u64 | size: u64]`) into the SST data block. `PendingSsts` generalizes to `PendingFiles` covering both `.sst` and `.blob` outputs before `DirSynced`.
  3. **MVCC, `CompactionFilter`, & GC:** `Version` tracks `BlobFileMetaData` (`total_bytes`, `garbage_bytes`, counting snapshot-visible historical versions as live until `oldest_snapshot_seq` advances past their shadowing sequence); compaction rewrites `BlobIndex` pointers (`O(24B)` instead of `O(val_len)`) unless the referenced `.blob` file exceeds `blob_garbage_ratio` (e.g., `0.5`) or an active non-noop `CompactionFilter` requires reading the value. Relocating surviving blob entries into a new `.blob` file preserves each entry's original sequence number (safe across active snapshots), while physical `.blob` file deletion waits until the last referencing `Version` / `SuperVersion` drops. `DB::contains_key` resolves `ValueType::BlobIndex` in **`0` blob reads**, and `DB::get_pinned` caches/pins blob payloads in `BlockCachePool` under `(member_id, blob_file_num, offset)` (collision-free with SST blocks because `.sst` and `.blob` share `FileNumbers`).
