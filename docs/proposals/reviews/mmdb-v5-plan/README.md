# Review of the MMDB execution plan

The [revised plan](../../mmdb-v5-execution-plan.md) contains the decisions and test procedures. The reports preserve each reviewer's reasoning, including the claims corrected below.

All four local CLIs used their configured default models and the same [English brief with the exact plan under review](input.txt). They ran in parallel, in fresh sessions with separate read-only MMDB and VSDB copies. Each session saw the uncommitted plan on MMDB `8aacd0f` and VSDB `9712c0e`. The SHA-256 of the reviewed plan was `d1931860f92a2448acd8f314b83053bc1078d8ec144906a5fe3fccaacd7cc6d2`. Grok's headless shell request was declined and OpenCode's first response ended after inspection. Each returned its full review after an English follow-up in its own session.

The 15% foreground-write, 20% L0-stall and 10% grouped-read targets and the 5% control guardrail are proposed planning thresholds. The reviewers recommended preregistration. Their suggested percentages and queue caps varied. A/A calibration and matched-load experiments will determine which effects are actually measurable. The existing point-operation trials used an explicit flush before the warm read pass. They do not measure steady-state compaction debt. [Recorded workload](../../mmdb-v5-vsdb-v18-improvements.md#measured-point-operations)

## What was checked during this review

The focused plan commands were rerun on x86_64 Linux with the resolved dependencies locked, including the exporter under `CI=1`. The full test names selected real cases. The L0 admission case still expects `InvalidArgument` and the manually constructed parallel compaction in the existing test is L1→L2. Future behavior gates need the new cases named in the plan.

The existing `v5_profile` benchmark ran in three fresh processes at immutable depths 1, 2 and 4. Each completed 20,000 reads and 20,000 writes, recorded both percentiles and peak RSS, and increased the completed flush count from 22 to 36. These single passes checked that the procedure works. They do not measure a candidate's improvement or select a 16-shard configuration.
