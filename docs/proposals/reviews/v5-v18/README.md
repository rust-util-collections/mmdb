# Independent reviews of the v5/v18 release proposal

The [final proposal](../../mmdb-v5-vsdb-v18-improvements.md) records the release recommendation. The four reports below preserve the reviewers' advice, including claims corrected during verification.

## Review inputs and provenance

All four local CLIs received the same [English brief](brief.txt), used their locally configured default model, and started fresh sessions. Each formal run had a private mount namespace with read-only MMDB and VSDB copies. Other reviewers' files, their output, and the live source directories were outside those mounts. The inputs were MMDB `4916abb`, VSDB `7082a88`, and the previous comparison appendix with its drivers and CSV. The joint draft's recommendations were withheld. A preliminary OpenCode session resolved the parent workspace, and agy's first headless attempts returned no report. Only the isolated runs below contributed to the decision. Report bodies exclude CLI progress and transport markers. Sandbox file links have been translated to repository destinations.

| Reviewer | Recommendation with the largest impact on the decision | Disposition |
|---|---|---|
| [Grok Build 1.0.92](grok.md) | Retire the one-byte fence tombstone, test compaction across cold prefix gaps, reduce the immutable queue to one. | Adopt the native fence. Measure gap rewrites after removing it. Compare queue depths under a fixed budget before selecting a default. |
| [agy 1.5.17](agy.md) | Budget v5 queues and cache overflow at cutover, reduce repeated VerMap publications, measure snapshot capture under WAL sync, reconsider L0 flush sizing. | Promote memory sizing to the release gate. Trial bounded branch edits and mixed reader/writer workloads. Keep graph, shard placement and object allocation semantics intact during migration. |
| [Claude Code 2.1.332](claude.md) | Account for both evictable stores, decode through scoped pins, and reuse B+ tree leaf header information. | Adopt explicit cache accounting. Test scoped decoding and leaf-header reuse independently before committing to a public API. Claude Code reported that its inspection interface could not read the CSV and made no numerical claims from it. |
| [OpenCode 2.4.1](opencode.md) | Exercise foreground requests behind large same-shard writes, coalesce co-located updates, remove alleged per-node engine snapshot registration. | Adopt mixed batch sizes and a different-shard control. Use one MMDB batch for one semantic commit. Source inspection disproved the per-node registration premise. |

## Claims that changed the recommendation

- **A full flush queue can stall a write before the new active memtable fills.** VSDB's 2 GiB / 16-shard sizing example gives 16 MiB per write buffer. Grok's 1,280 MiB is nominal arithmetic for five buffer thresholds per shard. OpenCode's 128 MiB per shard is an arithmetic error. MMDB checks the number of submitted but not durable generations before admitting a nonempty write. A limit of one can therefore stall immediately after a freeze. Compare limits of 1, 2 and 4 under a fixed process budget. The segmented and overflow caches have separate capacities. agy's suggested overflow allowance at or below one segment would exclude exactly the blocks routed there. [VSDB sizing](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/core/src/common/engine/mmdb.rs#L1457-L1553) · [Flush queue](../../../../src/db/flush.rs) · [Cache admission and oversized-block test](../../../../src/cache/block_cache.rs)
- **A root lease, a snapshot registration and a scalar read have different costs.** `MmDB::get` calls the shard's `DB::get`. `RootLease` retains an immutable tree root and its reader. Internal page-cache hits may avoid an engine fetch. Explicit MMDB snapshot registration takes `DB::inner`, which the writer also holds during WAL sync. Measure fresh snapshot capture, held-view reads and scalar reads separately. Claude Code's duplicate leaf opens do exist, but `NodeView::open` performs constant-time header checks. A second open on the same bytes is neither another object read nor a full slot validation. [VSDB adapter](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/core/src/common/engine/mmdb.rs#L374-L397) · [Tree lookup](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/strata/src/basic/persistent_btree/mod.rs#L444-L605) · [Page decoder](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/strata/src/basic/persistent_btree/nodes.rs#L49-L100) · [MMDB snapshot registration and group commit](../../../../src/db.rs)
- **Multi-get has one bounded collection use case.** In HNSW, IDs within the current neighbor list are known before their vector distances are evaluated. The next expansion depends on those distances. Keep a single-list trial with input order, visit cap, filtering and missing values preserved. Require an improvement over scalar pinned decoding before expanding the API. [HNSW loop](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/strata/src/vecdex/hnsw.rs#L204-L245) · [Vector fetch](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/strata/src/vecdex/mod.rs#L1463-L1532)
- **L0 splitting changes both bytes rewritten and the stall signal.** Flush output can split at a metadata threshold. Automatic L0 selection takes the current L0 set and closes over overlapping L1 ranges, including tombstones. Prefix-aligned cuts can reduce a cold gap but cannot separate page and blob keys within one map prefix. Splitting each prefix into a separate SST can hit file-count limits sooner. Test native fences, size/prefix-based output cuts and range-parallel execution as separate changes. Whole-key Bloom budgets, two-word probe mixing and optional bottom-level elision are already implemented. [Flush construction](../../../../src/db.rs) · [L0 selection](../../../../src/compaction/leveled.rs) · [Filter implementation](../../../../src/sst/filter.rs) · [Level budgets](../../../../src/options.rs)
- **A group sync and a single atomic application change have different boundaries.** Co-located DagMap handles can address one MMDB batch containing child metadata, parent metadata and the edge. Separate batches in one writer group share work but retain their own WAL records. A buffered VerMap session can publish one working root under today's writer-exclusion contract. Any later spill must preserve the `STAGE` records and next-ID floor. The Hotmint patch is a historical workload to replay. It cannot establish a present-day application's shard inventory or a reproduced crash defect. [DagMap registration](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/strata/src/dagmap/raw/mod.rs#L227-L264) · [Staging discipline](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/strata/src/basic/persistent_btree/persist.rs#L139-L175) · [Hotmint study scope](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/docs/evaluations/hotmint-v17.md)
- **One offline window can contain two independently checked conversions.** The v4 exporter already feeds a sorted visible-row iterator to `ingest_sorted` and publishes to an absent destination. Sorting an input does not make an occupied target span disjoint. The VSDB lifecycle converter reads legacy files and handles application-level conversions. Its markers do not identify the physical MMDB format or provide a cross-filesystem switch. Preserve logical IDs and shard placement, check ordered row digests and validate the actual writable v18 open with the expected geometry. Retain the complete old generation for rollback before new writes. [Exporter](../../../../tools/v4-export/src/main.rs) · [MMDB geometry checks](../../../../src/manifest/version_set.rs) · [VSDB converter](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/migration/src/universe.rs) · [Handle and directory migration](https://github.com/rust-util-collections/vsdb/blob/7082a888e8defc9a563653b14b0e0b16277f6496/migration/README.md)

## Checks actually run

Recomputed the 18 throughput cells from all 60 observations. The five-run medians for eight writers were 413,508 MMDB and 594,349 RocksDB puts/s without per-write sync, and 6,076 and 7,297 puts/s with sync. Pebble's unsynced acknowledgement can occur with bytes still buffered in user space. The compressible payload, Btrfs compression and short fresh-store runs leave queue attribution, physical bytes and end-to-end gains unresolved. [Raw times and SST counts](../../../benchmarks/point-ops/runs.csv) · [Pebble write options](https://github.com/cockroachdb/pebble/blob/v2.1.7/options.go#L350-L367)

On x86_64 Linux, the following existing tests passed against the individual checkouts. VSDB still used its v4 backend. Joint v18-on-v5 and AArch64 acceptance belong to the implementation phase.

| Checkout | Tests exercised | Passed |
|---|---|---:|
| MMDB | WAL seal/fence failure, simulated loss of the unsynced suffix across rotation, oversized block retained then invalidated | 3 |
| v4 exporter | Golden WAL/SST export, scan error with unpublished destination, WAL record compatibility | 3 |
| VSDB core | `read_view_test` and `sync_batch_test`, including the acknowledged batch process-kill case | 5 |
| VSDB collections | DagMap same-WAL registration, VecDex rejecting an incomplete rebuild, bounded tree iteration with large values, COW reuse of unaffected blob descriptors | 4 |

The process-kill test checks recovery after an application exit. The MMDB rotation test separately simulates losing unsynced WAL bytes. Neither result measures a proposed performance gain.
